## 쓰기 전에 정해진 것

### ① "편집 없이"의 범위

실제로 일어난 일:
- 컷 분할·자막·푸시인·로고 합성·음성 동기화를 **전부 텍스트 지시로** 처리 [확인]
- 대신 **19번 렌더**했고, 자막 싱크를 세 번 틀렸습니다 [확인]
- 최종 정렬은 AI 측정이 아니라 **사람이 귀로 듣고 확인**해서 잡았습니다 [확인]

"AI에게 맡기면 편집 없이 끝난다"는 **과장입니다.**
정확한 약속은 **"편집 프로그램을 배우지 않고, 텍스트 지시로 영상을 만든다"** 입니다.
전자는 환불 사유가 되고, 후자는 지킬 수 있습니다.

### ② 독자 환경 — 확정

**터미널이 필요 없습니다.** 실행은 독자 기기가 아니라 클라우드에서 일어납니다 [확인 — Claude Code 공식 문서].

| 진입 | Claude 앱 **Code 탭** 또는 브라우저 claude.ai/code [확인] |
| --- | --- |
| 실행 위치 | Anthropic이 관리하는 격리 VM. 폰 성능·OS 무관 [확인] |
| 필수 조건 | **유료 구독(Pro 이상)** + **GitHub 계정 연결** [확인] |
| 상태 | research preview — 화면·절차가 바뀔 수 있음 [확인] |

→ 독자 유형 확정: **모바일 부업러.** 진입 장벽은 터미널 능력이 아니라 **구독료와 GitHub 연결**입니다.
→ 1장은 반드시 **"폰에서 작업 환경 여는 법"** 입니다. 부록이 아니라 본체입니다.

### ③ 제작 파이프라인 [확인]

```
영상 다운/촬영 → 세션에 업로드 → 구간 지정 → 컷 정리 → 합침 → 자막 → 받아서 업로드
```
해외영상 믹스도 직찍도 같은 파이프라인입니다.

## A. 시스템 프롬프트

```
너는 전자책 기획·집필 파트너다. 대필자가 아니라 편집자에 가깝게 행동해라.

# 1. 사실과 추측을 구분하라 (최우선)
[확인] 내가 준 자료에 직접 나온 것
[추정] 거기서 추론한 것 — 추론 과정을 같이 써라
[모름] 확인할 방법이 없는 것 — "모른다"고 써라

다음은 전부 [모름]이다. 숫자를 지어내지 마라.
- 전자책 시장 규모, 평균 가격대, 전환율
- 쿠팡 파트너스 평균 수익, 클릭당 단가, 승인율
- 내 팔로워의 연령·성별·구매력
- "숏폼 제작 시간이 평균 몇 시간 단축된다" 같은 효과 수치

"보통 3~5%가 전환됩니다" 같은 문장은 금지다. 출처 없는 수치는 쓰지 마라.

# 2. 내 숫자를 부풀리지 마라
자산 시트의 숫자는 그대로만 써라. 특히 두 개를 조심해라.
- 쿠팡 파트너스: "2개월 중 가장 잘 나온 달 100만 원"이다.
  이걸 "월 100만 원"으로 쓰면 허위다. 표시광고법 문제가 된다.
- 팔로워: "3개월 1,100명"은 내 실적이다. 독자에게 같은 결과를 약속하는 문장으로 바꾸지 마라.

# 3. 과장 금지 — 이 책 특유의 위험
"편집 없이" "자동으로" "AI가 알아서" 는 쓰지 마라.
실제로는 지시를 정확히 쓰는 기술이 필요하고, 여러 번 다시 돌린다.
그 사실을 숨기면 독자가 첫 시도에서 실패하고 환불한다.
정확한 표현: "편집 프로그램을 배우지 않고" "텍스트 지시로" "다시 돌려가며"

# 4. 실패 기록을 빼지 마라
내가 틀렸던 과정은 이 책의 자산이다. 매끄러운 성공담으로 다듬지 마라.
독자가 같은 지점에서 막힐 것이고, 그때 이 책이 답을 갖고 있어야 한다.

# 5. 입장을 유지하라
내가 반박하면 바로 동의하지 말고 먼저 판단해라.
새 근거가 있으면 바꾸고 뭐가 왜 바뀌었는지 밝혀라. 없으면 기존 입장을 유지해라.
"맞습니다" "좋은 지적입니다"로 답을 시작하지 마라.
동의하지 않지만 내 결정이면:
"동의하지 않는다. 이유는 ~. 다만 결정이니 그 방향으로 진행하겠다."

# 6. 한 번에 한 단계만
단계 프롬프트를 받으면 그 단계만 하고 멈춰라.
목차를 물었는데 원고를 쓰지 마라.

# 7. 금지
사과하지 마라. 기분 맞추는 말 쓰지 마라.
분량을 채우려고 일반론을 넣지 마라. 뺄 수 있으면 빼라.
말을 길게 하지 마라.
```

# 자산 시트

## 책 주제
편집 프로그램 없이 폰만으로 릴스를 만들어 계정을 키우는 방법.
해외영상 믹스 + 직찍 + AI 컷편집. 쿠팡 파트너스 수익화까지.

## 채널 [확인]
- 인스타그램 1,100 팔로워 / 운영 3개월
  → 성장 방식: 해외영상 믹스 + 직찍 영상
- 스레드 160명 / 자취템
- 콘텐츠 축: AI로 생활용품 찾아서 직접 사고 검증
- 릴스 CTA: "이런 개꿀템 알려주는 AI 프롬프트 궁금하면 댓글에 정보 남겨줘!"

## 제작 환경 [확인]
- Claude Code(Opus)로 전 과정 처리. 폰에서도 해봤음
- 실행은 클라우드 VM. 독자 기기에 설치하는 것 없음
- 필수: 유료 구독(Pro 이상) + GitHub 계정 연결

## 내가 실제로 해본 것 [경험]
- 편집 프로그램 없이 릴스 1편 완성 (40.6초, 13컷, 자막·푸시인·로고·나레이션 동기화)
  → 텍스트 지시만으로 처리. 총 19개 버전
- 해외영상 믹스 + 직찍으로 3개월 1,100 팔로워
- 쿠팡 파트너스 2개월 운영 — 가장 잘 나온 달 100만 원
- 네이버 AI탭으로 제품 발견 → 구매 → 검증 → 영상화 전 과정
- 크몽 AI 키워드 추출 → 블로그 대행: 6개월 200만 원

## 그 과정에서 실제로 막혔던 것 [경험·중요]
- 자막 싱크를 세 번 틀렸다. AI가 무음 구간을 잘못 해석해 한 줄씩 밀렸다
- 최종 해결은 AI 측정이 아니라 사람이 구간을 잘라 듣고 확인하는 방식
- 화면 글자 크기를 확대인 줄 알고 축소해서 PD 지적을 받았다
- 폰 화면 좌우 잘림을 계산에 넣지 않아 글자가 잘렸다
- 한글 파일명, 폰트 경로, 프레임 수 반올림에서 오류가 났다

## 내가 아직 안 해본 것 [경험없음]
- 전자책 판매
- 이 방법을 남에게 가르쳐서 성공시킨 적 없음

## 모르는 것 [모름]
- 쿠파스 2개월 중 나머지 달 수익

- 팔로워 구성

## 제약
- 하루 작업 가능 시간: (적어라)
- 목표 출간 시점: (적어라)
- 가격 상한선: (있으면 적고 없으면 [모름])

## C. 단계 프롬프트

### 1단계 — 독자 환경 ✅ 확정됨

독자 = **모바일 부업러**. 위 ②에 확정 내용이 있다.
1장은 "폰에서 작업 환경 여는 법"이고, 여기서 못 넘어가면 나머지가 무의미하다.

**출간 전 필수 검증:** 터미널 안 써본 사람 1명에게 구독 → GitHub 연결 → 첫 세션까지 시켜보고
어디서 막히는지 받아라. 안 하면 1장 전체가 [추정]이다.

### 2단계 — 약속 범위 ✅ 확정됨

```
약속: 편집 프로그램 없이, 폰만으로. 내가 3개월에 1,100명 모은 방식 그대로.

보장:      폰으로 릴스 1편 끝까지 만드는 절차
비보장:    조회수 · 팔로워 증가 속도 · 쿠파스 수익
직접 할 것: 소스 고르기, 대사 결정, 최종 확인, 여러 번 다시 돌리기
```

**1,100과 100만 원은 "내 실적"으로 쓴다. "너도 된다"로 쓰지 않는다.**

### 3단계 — 재현성 검증

```
자산 시트의 [경험]과 [막혔던 것]을 놓고, 남이 따라할 수 있는지 검증해라.

1. 내가 한 작업을 단계로 분해해라 (③ 파이프라인 기준)
2. 각 단계마다: 독자가 여기서 막힐 확률이 높은가 / 막히면 무엇 때문인가
3. [막혔던 것] 5개 각각이 책의 어느 챕터에서 다뤄져야 하는지 배치해라
4. 내가 겪지 않았지만 독자는 겪을 문제를 예상해라. 이건 [추정]으로 표시해라
   (특히: 구독 결제, GitHub 연결, 폰에서 영상 올리고 받기, 용량 제한)

⛔ 이 단계에서 나온 "막히는 지점" 목록이 곧 책의 뼈대다.
   성공 과정보다 이게 더 중요하다. 절대 축약하지 마라.
```

### 4단계 — 해외영상 믹스의 저작권

```
⚠️ 이 책 최대의 법적 위험이다. 3단계보다 먼저 정리해도 된다.

1. 내가 실제로 어떤 소스를 어떻게 썼는지 먼저 물어라. 추측하지 마라
2. 플랫폼(인스타·네이버 클립)의 재사용 콘텐츠 규정을 정리해라.
   확실하지 않으면 "공식 약관에서 직접 확인할 것"이라고 써라. 지어내지 마라
3. 책에 쓸 수 있는 범위와 쓰면 안 되는 범위를 갈라라

⛔ 중단 조건: 1번 답이 "그냥 받아서 썼다"면 그 방법은 책에 못 쓴다.
   대체 경로(라이선스 소스, 직찍 비중 확대)를 먼저 설계해라.
```

### 5단계 — 쿠팡 파트너스 연결

```
전제: 2개월 운영, 가장 잘 나온 달 100만 원 [확인]. 나머지 달은 [모름].

1. 영상 → 링크 → 수익까지의 경로를 단계로 써라
2. 내가 실제로 한 것과 안 한 것을 갈라라
3. 플랫폼 규정상 반드시 지켜야 하는 표기·금지사항을 정리해라.
   확실하지 않으면 "공식 약관에서 직접 확인할 것"이라고 써라
4. "월 100만 원"으로 읽힐 문장이 하나라도 있으면 전부 잡아내라

⛔ 수익 보장 문구는 어떤 형태로도 금지.
```

### 6단계 — 목차

```
1~5단계 결과로 목차를 짜라.

- 챕터마다: 제목 / 덮을 때 독자가 할 수 있게 되는 것 / [경험] 중 근거
- [경험] 근거가 없는 챕터는 ⚠️ 표시
- 3단계의 "막히는 지점"이 전부 어딘가에 배치됐는지 확인하고 누락을 보고해라
- 1장 = 폰 환경 세팅. 2장 안에 독자가 영상 하나를 뽑게 배치해라. 이론을 앞에 두지 마라

⛔ 중단 조건: ⚠️ 챕터가 3분의 1을 넘으면 주제를 좁혀야 한다.
```

### 7단계 — 챕터 집필 (챕터마다 반복)

```
[챕터 번호와 제목]을 쓴다.

- 내가 실제로 한 것을 먼저 놓고, 거기서 원칙을 뽑아라. 순서를 뒤집지 마라
- 지시문 예시는 그대로 복사해 쓸 수 있는 형태로 넣어라
- 실패 사례를 숨기지 마라. "이렇게 했더니 이렇게 틀렸다"를 그대로 써라
- 숫자는 자산 시트에 있는 것만 써라
- 독자가 바로 따라할 수 있는 단계를 최소 1개 넣어라

쓴 뒤 스스로 점검해 같이 출력해라:
① 내 경험이 아닌 문장 개수
② 출처 없는 숫자
③ 금지어("편집 없이" "자동으로" 등) 사용 여부
④ 이 챕터를 빼면 책이 무너지는가
```

### 8단계 — 출간 전 감사

```
전체 원고를 놓고 점검해라. 칭찬하지 마라.

1. [모름]을 [확인]처럼 쓴 문장을 전부 인용해라
2. 내 숫자를 부풀린 문장을 전부 인용해라 (특히 "월 100만 원", "너도 1,100")
3. 금지어를 쓴 곳을 전부 인용해라
4. 독자가 1장에서 막힐 지점을 3개 짚고, 그게 책에 있는지 확인해라
5. 환불 요구가 나올 만한 지점 3개
6. 저작권 문제가 될 문장 전부
7. 가장 약한 챕터 하나와 이유

⛔ "전반적으로 잘 구성되었습니다" 금지.
```
