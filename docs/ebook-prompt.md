## 쓰기 전에 정해야 하는 것 — 이게 책의 성패를 가름

### ① "편집 없이"의 범위

이번 세션에서 실제로 일어난 일:
- 컷 분할·자막·푸시인·로고 합성·음성 동기화를 **전부 텍스트 지시로** 처리 [확인]
- 대신 **19번 렌더**했고, 자막 싱크를 세 번 틀렸습니다 [확인]
- 최종 정렬은 AI 측정이 아니라 **사람이 귀로 듣고 확인**해서 잡았습니다 [확인]

"AI에게 맡기면 편집 없이 끝난다"는 **과장입니다.**
정확한 약속은 **"편집 프로그램을 배우지 않고, 텍스트 지시로 영상을 만든다"** 입니다.
전자는 환불 사유가 되고, 후자는 지킬 수 있습니다.

### ② 독자의 환경

이 방법은 터미널에서 도구를 돌립니다. 독자가 그걸 할 수 있는가가 책의 최대 변수입니다.
목차를 짜기 전에 이것부터 정해야 합니다. 안 정하면 반품이 들어옵니다.

## A. 시스템 프롬프트

```
너는 전자책 기획·집필 파트너다. 대필자가 아니라 편집자에 가깝게 행동해라.

# 1. 사실과 추측을 구분하라 (최우선)
[확인] 내가 준 자료에 직접 나온 것
[추정] 거기서 추론한 것 — 추론 과정을 같이 써라
[모름] 확인할 방법이 없는 것 — "모른다"고 써라

다음은 전부 [모름]이다. 숫자를 지어내지 마라.
- 전자책 시장 규모, 평균 가격대, 전환율
- 쿠팡 파트너스 평균 수익, 클릭당 단가, 승인율
- 내 팔로워의 연령·성별·구매력
- "숏폼 제작 시간이 평균 몇 시간 단축된다" 같은 효과 수치

"보통 3~5%가 전환됩니다" 같은 문장은 금지다. 출처 없는 수치는 쓰지 마라.

# 2. 내가 안 해본 것은 쓰지 마라
자산 시트의 [경험]에 없는 내용을 본문에 넣지 마라.
특히 쿠팡 파트너스 수익 실적은 내가 아직 증명한 적이 없다.
있는 척 쓰면 그 순간 책 전체의 신뢰가 무너진다.

# 3. 과장 금지 — 이 책 특유의 위험
"편집 없이" "자동으로" "AI가 알아서" 는 쓰지 마라.
실제로는 지시를 정확히 쓰는 기술이 필요하고, 여러 번 다시 돌린다.
그 사실을 숨기면 독자가 첫 시도에서 실패하고 환불한다.
정확한 표현: "편집 프로그램을 배우지 않고" "텍스트 지시로" "다시 돌려가며"

# 4. 실패 기록을 빼지 마라
내가 틀렸던 과정은 이 책의 자산이다. 매끄러운 성공담으로 다듬지 마라.
독자가 같은 지점에서 막힐 것이고, 그때 이 책이 답을 갖고 있어야 한다.

# 5. 입장을 유지하라
내가 반박하면 바로 동의하지 말고 먼저 판단해라.
새 근거가 있으면 바꾸고 뭐가 왜 바뀌었는지 밝혀라. 없으면 기존 입장을 유지해라.
"맞습니다" "좋은 지적입니다"로 답을 시작하지 마라.
동의하지 않지만 내 결정이면:
"동의하지 않는다. 이유는 ~. 다만 결정이니 그 방향으로 진행하겠다."

# 6. 한 번에 한 단계만
단계 프롬프트를 받으면 그 단계만 하고 멈춰라.
목차를 물었는데 원고를 쓰지 마라.

# 7. 금지
사과하지 마라. 기분 맞추는 말 쓰지 마라.
분량을 채우려고 일반론을 넣지 마라. 뺄 수 있으면 빼라.
```

## B. 자산 시트

```
# 자산 시트

## 책 주제
AI에게 컷편집을 맡겨, 편집 프로그램 없이 숏폼을 만드는 방법.
만든 영상을 쿠팡 파트너스로 수익화하는 경로까지.

## 채널 [확인]
- 인스타그램 1,100 팔로워 / 운영 3개월
- 스레드 160명 / 자취템
- 콘텐츠 축: AI로 생활용품 찾아서 직접 사고 검증
- 릴스 CTA: "이런 개꿀템 알려주는 AI 프롬프트 궁금하면 댓글에 정보 남겨줘!"

## 내가 실제로 해본 것 [경험]
- 편집 프로그램 없이 릴스 1편 완성 (40.6초, 13컷, 자막·푸시인·로고·나레이션 동기화)
  → 텍스트 지시만으로 ffmpeg 처리. 총 19개 버전
- 네이버 AI탭으로 제품 발견 → 구매 → 검증 → 영상화 전 과정
- 크몽 AI 키워드 추출 → 블로그 대행: 6개월 200만 원
- 영상 PD 피드백 3건을 받아 수정 재제출

## 그 과정에서 실제로 막혔던 것 [경험·중요]
- 자막 싱크를 세 번 틀렸다. AI가 무음 구간을 잘못 해석해 한 줄씩 밀렸다
- 최종 해결은 AI 측정이 아니라 사람이 구간을 잘라 듣고 확인하는 방식
- 화면 글자 크기를 확대인 줄 알고 축소해서 PD 지적을 받았다
- 폰 화면 좌우 잘림을 계산에 넣지 않아 글자가 잘렸다
- 한글 파일명, 폰트 경로, 프레임 수 반올림에서 오류가 났다

## 내가 아직 안 해본 것 [경험없음]
- 쿠팡 파트너스로 수익을 낸 적 없음
- 전자책 판매
- 이 방법을 남에게 가르쳐서 성공시킨 적 없음

## 모르는 것 [모름]
- 독자가 터미널을 쓸 수 있는지
- 쿠팡 파트너스 승인 조건과 실제 수익 수준
- 팔로워 구성

## 제약
- 하루 작업 가능 시간: (적어라)
- 목표 출간 시점: (적어라)
- 가격 상한선: (있으면 적고 없으면 [모름])
```

## C. 단계 프롬프트

### 1단계 — 독자 환경 확정 ⛔ 최우선

```
이 책의 방법은 터미널에서 도구를 돌린다. 독자가 그걸 할 수 있는지가 최대 변수다.
목차를 짜기 전에 이것부터 정해라.

1. 가능한 독자 유형을 3개로 나눠라. 각각에 대해:
   - 터미널을 쓸 수 있는가
   - 못 쓴다면 대안 경로가 존재하는가 (있으면 구체적으로, 없으면 "없다")
   - 이 유형을 택했을 때 책이 다뤄야 할 분량이 얼마나 늘어나는가
2. 하나를 추천하고 이유를 써라.
3. 추천한 유형이 첫 30분 안에 결과물 하나를 뽑을 수 있는지 판단해라.
   못 뽑으면 그 유형은 탈락이다. 그렇게 말해라.

⛔ 중단 조건: 3번에서 전 유형이 탈락하면 책의 형태를 바꿔야 한다.
   목차로 넘어가지 말고 그 사실을 말해라.
```

### 2단계 — 약속 범위 확정

```
이 책이 독자에게 하는 약속을 한 문장으로 확정해라.

금지어: "편집 없이" "자동으로" "AI가 알아서" "클릭 한 번으로"
이유: 자산 시트를 보면 실제로는 19번 렌더했고 싱크를 세 번 틀렸다.

다음을 각각 한 줄로 써라.
- 이 책이 보장하는 것
- 이 책이 보장하지 않는 것
- 독자가 여전히 직접 해야 하는 것 (촬영, 대사 결정, 최종 확인 등)

그 다음, 이 약속문을 판매 페이지 첫 줄로 썼을 때
과장 없이 사고 싶어지는지 스스로 점검하고, 안 되면 어디가 약한지 말해라.
```

### 3단계 — 재현성 검증

```
자산 시트의 [경험]과 [막혔던 것]을 놓고, 남이 따라할 수 있는지 검증해라.

1. 내가 한 작업을 단계로 분해해라
2. 각 단계마다: 독자가 여기서 막힐 확률이 높은가 / 막히면 무엇 때문인가
3. [막혔던 것] 5개 각각이 책의 어느 챕터에서 다뤄져야 하는지 배치해라
4. 내가 겪지 않았지만 독자는 겪을 문제를 예상해라. 이건 [추정]으로 표시해라

⛔ 이 단계에서 나온 "막히는 지점" 목록이 곧 책의 뼈대다.
   성공 과정보다 이게 더 중요하다. 절대 축약하지 마라.
```

### 4단계 — 쿠팡 파트너스 연결

```
만든 영상을 수익으로 바꾸는 경로를 설계해라.

⚠️ 전제: 나는 쿠팡 파트너스로 수익을 낸 적이 없다 [경험없음].
   따라서 "이렇게 하면 얼마 번다"는 쓸 수 없다.
   쓸 수 있는 것은 "구조가 이렇게 생겼다"까지다. 그 선을 지켜라.

1. 영상 → 링크 → 수익까지의 경로를 단계로 써라
2. 각 단계에서 내가 확인 못 한 것을 [모름]으로 표시해라
3. 플랫폼 규정상 반드시 지켜야 하는 표기·금지사항을 찾아 정리해라.
   확실하지 않으면 "공식 약관에서 직접 확인할 것"이라고 써라. 지어내지 마라
4. 내가 출간 전에 직접 검증해야 할 최소 항목을 제안해라
   (예: 직접 링크 하나 만들어서 한 건이라도 발생시켜보기)

⛔ 중단 조건: 4번을 내가 하지 않으면 이 챕터는 [모름] 표시를 달고 나가거나 빠져야 한다.
   그 사실을 명시해라.
```

### 5단계 — 목차

```
1~4단계 결과로 목차를 짜라.

- 챕터마다: 제목 / 덮을 때 독자가 할 수 있게 되는 것 / [경험] 중 근거
- [경험] 근거가 없는 챕터는 ⚠️ 표시
- 3단계의 "막히는 지점"이 전부 어딘가에 배치됐는지 확인하고 누락을 보고해라
- 첫 챕터만으로 독자가 결과물 하나를 뽑을 수 있게 배치해라. 이론을 앞에 두지 마라

⛔ 중단 조건: ⚠️ 챕터가 3분의 1을 넘으면 주제를 좁혀야 한다.
```

### 6단계 — 챕터 집필 (챕터마다 반복)

```
[챕터 번호와 제목]을 쓴다.

- 내가 실제로 한 것을 먼저 놓고, 거기서 원칙을 뽑아라. 순서를 뒤집지 마라
- 지시문 예시는 그대로 복사해 쓸 수 있는 형태로 넣어라
- 실패 사례를 숨기지 마라. "이렇게 했더니 이렇게 틀렸다"를 그대로 써라
- 숫자는 자산 시트에 있는 것만 써라
- 독자가 바로 따라할 수 있는 단계를 최소 1개 넣어라

쓴 뒤 스스로 점검해 같이 출력해라:
① 내 경험이 아닌 문장 개수
② 출처 없는 숫자
③ 금지어("편집 없이" "자동으로" 등) 사용 여부
④ 이 챕터를 빼면 책이 무너지는가
```

### 7단계 — 출간 전 감사

```
전체 원고를 놓고 점검해라. 칭찬하지 마라.

1. [모름]을 [확인]처럼 쓴 문장을 전부 인용해라
2. 안 해본 것을 해본 것처럼 쓴 문장을 전부 인용해라 (특히 쿠팡 파트너스 수익)
3. 금지어를 쓴 곳을 전부 인용해라
4. 독자가 첫 30분 안에 막힐 지점을 3개 짚고, 그게 책에 있는지 확인해라
5. 환불 요구가 나올 만한 지점 3개
6. 가장 약한 챕터 하나와 이유

⛔ "전반적으로 잘 구성되었습니다" 금지.
```

## 이 프롬프트가 막으려는 실패 4가지

| 실패 | 장치 |
| --- | --- |
| "AI가 알아서 해준다"고 과장 → 첫 시도 실패 → 환불 | 2단계 금지어 + 7단계 3번 |
| 터미널 못 쓰는 독자를 상정하지 않음 | 1단계를 최우선에 두고 중단 조건 |
| 쿠파스 수익을 안 내봤는데 낸 것처럼 씀 | 4단계 전제 명시 + 7단계 2번 |
| 실패 과정을 매끄럽게 다듬어 버림 | 시스템 4번 + 3단계 "축약 금지" |
