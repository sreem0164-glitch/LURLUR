# 1장. 폰에서 작업 환경 열기

> **여기서 가장 많이 이탈한다. 그래서 가장 먼저, 가장 자세히 쓴다.**

## 왜 폰으로 되는가

핵심부터. **당신 폰이 영상을 처리하는 게 아니다.**

```
당신 폰  →  (지시)  →  클라우드 서버에서 처리  →  결과물만 폰으로
```

영상 편집은 원래 컴퓨터 성능을 먹는다. 그런데 처리가 **폰 밖에서** 일어나면 폰 성능은 상관이 없다.
Claude Code라는 도구가 그렇게 동작한다 — 공식 문서에 **"브라우저, 폰, 데스크톱 앱, 터미널에서 클라우드 세션을 실행한다"** 고 적혀 있다 [확인].

진입 경로는 둘이다 [확인].
- **Claude 앱의 `Code` 탭**
- 브라우저에서 `claude.ai/code`

## 준비물 2개 — 솔직히 말한다

### ① 유료 구독

**무료 계정으로는 안 된다.** 공식 문서상 Pro · Max · Team 사용자 대상이다 [확인].

월 얼마인지는 이 책에 쓰지 않는다. **가격은 바뀐다.** 바뀐 숫자를 책에 박아두면 그게 거짓말이 된다.
결제 전에 공식 페이지에서 직접 확인해라.

> **판단 기준**
> 이 도구로 영상 4편을 만들 생각이면 구독료를 편당으로 나눠봐라.
> 편집 외주 단가와 비교해서 판단하는 게 맞다. **"AI니까 공짜"가 아니다.**

### ② GitHub 계정 연결

**여기가 진짜 관문이다.** 개발자가 아니면 "깃허브"라는 단어부터 낯설다.

깃허브는 **파일을 보관하는 곳**이라고만 이해하면 된다. 코딩을 배울 필요는 없다.
작업할 공간(저장소)이 하나 필요하고, 그걸 연결해줘야 세션이 돌아간다.

```
□ github.com 가입 (이메일만 있으면 된다)
□ 비어 있는 저장소 1개 생성 — 이름은 아무거나. 예: my-reels
□ Claude 쪽에서 GitHub 연결 승인
□ Code 탭에서 그 저장소를 골라 첫 세션 시작
```

> **저자가 이 절차를 직접 검증했다** [확인].
> 다만 기기·계정 상태에 따라 화면이 다를 수 있다. 막히면 대부분 "저장소를 안 만들어서"
> 또는 "연결 권한을 안 준 것"이다 [추정].

## 알아둬야 할 제약 3개 [확인]

| 제약 | 뜻 | 대응 |
| --- | --- | --- |
| **사용량 한도** | 다른 Claude 사용과 한도를 공유한다 | 렌더를 아껴라. 내가 19번 돌린 건 좋은 예가 아니다 |
| **세션 만료** | 오래 안 쓰면 작업 환경이 회수된다 | 작업은 몰아서. 중요 파일은 받아둬라 |
| **연구 프리뷰** | 화면·절차가 바뀔 수 있다 | 이 책의 **순서**를 따르되 **화면**은 그대로일 거라 믿지 마라 |

# 2장. 파일 준비 — 시작도 못 하고 막히는 자리

내가 오류를 낸 곳이 세 군데다. 전부 영상이 아니라 **파일** 문제였다 [확인].

## ① 한글 파일명

**파일 이름에 한글을 쓰지 마라.**

내 소스 파일 중에 `KakaoTalk_20250901_...mp4` 같은 것과 한글이 섞인 것이 있었고, 거기서 오류가 났다 [확인].

```
❌ 세면대 청소 영상(최종).mp4
❌ 1번컷.mp4
⭕ clip01.mp4
⭕ before_sink.mp4
```

**규칙: 영문 소문자 + 숫자 + 밑줄만.** 공백도 괄호도 쓰지 마라.

올리기 전에 폰에서 이름부터 바꿔라. 나중에 바꾸면 지시문을 전부 다시 써야 한다.

## ② 한글 폰트

**자막에 한글을 쓰려면 한글 폰트가 있어야 한다.** 없으면 글자가 `□□□` 로 나온다.

나는 **나눔스퀘어라운드 Bold** 를 썼다 [확인]. 무료 배포 폰트다.

```
□ 폰트 파일(.ttf/.otf)을 세션에 같이 올린다
□ 첫 자막 테스트에서 글자가 깨지는지 먼저 확인한다
```

> **순서가 중요하다.** 영상 다 만들고 자막 넣을 때 폰트가 없는 걸 알면, 그때부터 다시다.
> **1컷짜리 테스트로 폰트부터 확인해라.**

## ③ 파일 개수와 순서

나는 **클립 11개를 올려서 9개 구간만 썼다** [확인].

올릴 때 이렇게 정리해라.

```
clip01_before.mp4    ← 뭘 찍은 건지 이름에 넣는다
clip02_after.mp4
clip03_screen.mp4
```

이름에 내용이 들어가 있으면 **"clip02의 0.4초부터"** 라고 지시할 수 있다.
이름이 `KakaoTalk_...902984.mp4` 면 당신도 그게 뭔지 모른다.

## 2장 체크리스트

```
□ 파일명 전부 영문+숫자
□ 한글 폰트 파일 업로드 완료
□ 1컷 자막 테스트로 폰트 확인 완료
□ 파일 이름만 보고 어떤 장면인지 알 수 있다
```

# 3장. 구간 지정 — "적당히"라고 쓰면 안 되는 이유

> **이 책에서 가장 실용적인 장이다. 여기만 익혀도 본전이다.**

## 왜 "적당히 잘라줘"가 안 되나

AI는 당신 영상을 **보고 판단하지 않는다.** 당신이 말한 숫자대로 자른다.
"적당히"라고 하면 적당히 자르는 게 아니라, **아무 데나** 자른다.

## 실제로 내가 쓴 형식

컷 시트를 이렇게 만들었다 [확인].

| # | 파일 | 인~아웃 | 길이 | 내용 |
| --- | --- | --- | --- | --- |
| 1 | clip01 | 0.4 ~ 1.3 | 0.9s | Before 수전 |
| 2 | clip02 | 0.4 ~ 1.5 | 1.1s | After 수전 |
| 3 | clip01 | 0.2 ~ 4.7 | 4.5s | 세면대 전체 |

**이게 전부다.** 파일명, 시작 초, 끝 초. 세 개면 된다.

```
지시문 예시
─────────────
clip01의 0.4초부터 1.3초까지 잘라서 1번 컷으로.
clip02의 0.4초부터 1.5초까지 잘라서 2번 컷으로.
두 개를 순서대로 이어붙여줘.
```

## 초 단위를 어떻게 아나

폰 갤러리에서 영상을 열고 **한 프레임씩 넘겨보면서** 적어라. 원시적이지만 이게 제일 빠르다.

> **0.1초 단위로 적어라.** "1초쯤"이 아니라 "0.4"다.
> 훅에서 0.2초 차이는 크다. 뒤쪽 컷에서는 덜하다.

## 길이 감각 — 내 영상 기준 [확인]

| 구간 | 길이 |
| --- | --- |
| 훅 (Before) | 0.9초 |
| 훅 (After) | 1.1초 |
| 상황 설명 | 4.5초 |
| 화면 녹화 | 2.5~3.0초 |
| 작업 장면 | 3.5~5.0초 |
| **전체** | **31.9초** |

**훅은 1초 안팎, 설명은 4~5초.** 이 비율이 무너지면 앞이 늘어진다.

## 3장 체크리스트

```
□ 컷 시트를 표로 만들었다 (파일명 / 인 / 아웃)
□ 모든 숫자가 0.1초 단위다
□ "적당히" "알아서" "괜찮게" 라는 단어가 지시문에 없다
```

# 4장. 합치기 — 여기서 첫 영상이 나온다

> **가장 쉬운 장이다.** 3장 컷 시트가 있으면 지시 한 번이면 된다.

## 첫 결과물부터 뽑아라

자막도 음성도 다 빼고, **자른 것만 이어붙인 영상**을 먼저 만들어라.

```
지시문 예시
─────────────
위 컷 시트대로 전부 잘라서 순서대로 이어붙여줘.
1080x1920, 30fps, H.264로 내보내줘.
자막은 아직 넣지 마.
```

**이유: 여기서 순서 문제가 보인다.** 자막까지 다 넣고 나면 순서를 바꾸기 싫어진다.

## 내가 순서를 틀렸던 기록 [확인]

스펀지로 문지르는 장면을 **앞쪽에 뒀다.** 화면이 예뻐서 골랐다.

```
❌ 제품 등장 → AI에게 물어봄 → 써봄
   "이미 아는 걸 왜 물어보지?"

⭕ 문제 발견 → AI에게 물어봄 → 제품 등장 → 써봄
   "나도 몰랐는데 이렇게 찾았다"
```

**컷을 하나도 안 바꾸고 위치만 옮겨서 고쳤다.**
이걸 자막 다 넣은 뒤에 발견했으면 훨씬 귀찮았을 거다.

## 출력 규격은 처음부터 맞춰라 [확인]

| 항목 | 값 |
| --- | --- |
| 해상도 | **1080 × 1920** (9:16) |
| 프레임 | 30fps |
| 영상 코덱 | **H.264** |
| 오디오 | **AAC** |

인스타 공식 권장이 9:16 · H.264 · AAC다 [확인]. 안 맞으면 플랫폼이 알아서 변환하고, **그 변환이 화질을 깎는다** [추정].

> **⚠️ 오디오 트랙 없는 영상 주의**
> 음성을 안 넣을 거라도 **무음 오디오 트랙**은 넣어라.
> 나는 네이버 클립에 올리려다 오디오 트랙을 요구해서 다시 만들었다 [확인].
> 인스타 공식 "추천하지 않는 릴스" 목록에도 **음소거 영상**이 있다 [확인].

## 검은 띠(레터박스) 처리

가로 영상을 세로에 넣으면 위아래가 비는데, **테두리 있는 영상은 추천에서 제외된다** [확인].

나는 **같은 화면을 흐리게 깔아서** 채웠다 (`gblur` 처리) [확인].

```
지시문 예시
─────────────
이 컷은 가로라 위아래가 비는데,
같은 화면을 크게 확대하고 강하게 블러 처리해서 배경으로 깔아줘.
```

> **성과 차이 데이터는 없다 [모름].** 검은 띠를 없애는 게 목적이고, 미관은 부수적이다.

## 4장 통과 기준

```
□ 폰으로 받아서 끝까지 봤다
□ 순서가 "몰랐다 → 알게 됐다" 로 흐른다
□ 검은 띠가 없다
□ 오디오 트랙이 있다
```

**여기까지가 첫 영상이다. 자막 없이도 올릴 수 있다.**

# 5장. 자막과 싱크 — 내가 세 번 틀린 곳

> **이 책에서 가장 두꺼운 장이다. 이유는 하나 — 여기서 제일 많이 틀렸다.**

## 5-1. 자막 톤 — 설명체를 버려라

첫 버전 자막은 전부 설명이었다. 밋밋했다.

| ❌ 설명체 | ⭕ 하소연체 |
| --- | --- |
| "이랬는데" | **"아니 이게 뭐야"** |
| "2천원으로 이렇게 됨" | **"2천원에 이게 된다고?"** |
| "AI탭한테 물어봄" | **"그래서 AI탭한테 물어봤거든"** |
| "단점까지 알려주네" | **"근데 단점까지 알려주네?"** |
| "팔 좀 아프긴 함" | **"아 근데 팔 좀 아파"** |

### 규칙 3개 [확인]

1. **`아니` / `근데` / `그래서`로 문장을 이어라** — 한 사람이 계속 말하는 흐름이 생긴다
2. **물음표를 살려라** — `된다고?` `알려주네?` 가 반응을 유도한다
3. **종결을 바꿔라** — `~함` `~됨` ❌ / `~거든` `~네?` `~지` `~야` ⭕

### 불평 한 줄은 반드시 넣어라

**"아 근데 팔 좀 아파"** — 이 한 줄을 빼면 영상이 광고가 된다.
좋은 말만 있는 후기는 후기로 안 읽힌다.

## 5-2. 폰트 크기 — 내가 쓴 값 [확인]

| 위치 | 크기 |
| --- | --- |
| 훅 | 64px |
| 3줄 자막 | 54px |
| 일반 | 60px |
| 화면 녹화 구간 | 60px (상단 배치) |

**스타일: 흰색 + 검은 테두리 5px.** 배경이 밝든 어둡든 읽힌다.

## 5-3. 싱크 — 실패 기록 전부 공개

음성(나레이션)을 넣으면 **자막과 음성이 맞아야 한다.** 여기서 세 번 틀렸다.

### ❌ 실패한 방법 1 — 무음 구간으로 자르기

"말과 말 사이 조용한 지점"을 찾아서 거기를 문장 경계로 삼았다.

**틀렸다.** 내 음성에는 무음이 **28개** 있었는데,
- 문장 **사이** 무음: 0.36초
- 문장 **안** 호흡: 0.30초

**길이로 구분이 안 된다** [확인]. 그래서 자막이 한 줄씩 밀렸다.

### ❌ 실패한 방법 2 — 음절 수로 배분하기

발화 구간 27개에 대본 13줄 177음절을 비율대로 나눴다.

**틀렸다.** 결과가 앞 버전과 거의 같아서 **틀린 걸 알 방법조차 없었다** [확인].
검증이 안 되는 방법은 맞아도 맞은 게 아니다.

### ⭕ 실제로 통한 방법 — 귀로 듣기

**AI에게 시간을 재게 하지 말고, 잘라서 들려달라고 해라.**

```
지시문 예시
─────────────
음성의 23.2초부터 24.9초까지만 잘라서 들려줘.
```

듣고 **"뭐라고 들리는지"만** 적으면 된다.

### ⚠️ 여기가 핵심이다 — 초를 읽으려 하지 마라

내가 영상을 보면서 "지금 몇 초"를 세려고 했더니 **반응 지연 때문에 1.9초씩 밀렸다** [확인].

**사람은 시계를 못 읽는다. 대신 귀는 정확하다.**

```
❌ 영상 보면서 "여기가 24초쯤" → 못 쓴다
⭕ 조각 듣고 "'살살 문지르래'로 들린다" → 정확하다
```

### 실제 대조 기록 [확인]

| 구간 | 내가 가정한 자막 | 실제로 들린 것 |
| --- | --- | --- |
| 8.9~10.4s | "일단 네이버 켜서" | **"이 꼴...어~"** |
| 23.2~24.9s | "그래서 해봤지" | **"살살 문지르래"** |
| 30.2~33.4s | "이거 전부 네이버 AI탭으로" | **"다이소 2천원이야"** |

**세 개 다 틀렸다.** 한 줄씩 밀려 있었다.

이 대조로 전 구간을 다시 정렬했고, **컷 경계 오차가 ±0.017초 안에** 들어왔다 [확인].

### 따라하는 순서

```
1. 음성을 넣고 자막을 대강 배치한다
2. 의심되는 구간 3~5개를 고른다 (특히 중반 이후)
3. 각 구간을 잘라서 들려달라고 한다
4. 들린 대로 받아쓴다 — 초는 신경 쓰지 않는다
5. 어긋난 곳부터 전체를 다시 맞춘다
```

> **중반 이후를 의심해라.** 밀림은 누적된다. 앞은 맞는데 뒤가 틀린 경우가 대부분이다.

## 5장 체크리스트

```
□ 자막에 "~함" "~됨" 이 없다
□ 불평·실패가 한 줄 이상 있다
□ 구간 3개 이상을 잘라 들어서 확인했다
□ 초를 눈으로 세지 않았다
```

# 6장. 안전영역 — 편집 화면은 거짓말을 한다

편집 화면에서는 멀쩡했다. **폰으로 열어보니 자막 끝 글자가 잘려 있었다** [확인].

## 숫자 3개만 외워라 [확인]

```
세로 1920 기준
┌─────────────────┐
│  y < 220        │  ← 상단 UI. 여기 위로 자막 넣지 마라
├─────────────────┤
│                 │
│   안전 구간      │
│                 │
├─────────────────┤
│  y > 1470       │  ← 하단 UI. 여기 아래로 자막 넣지 마라
└─────────────────┘
        ↑
  좌우: x 100 ~ 980 안에
```

| 경계 | 값 | 근거 |
| --- | --- | --- |
| 하단 UI | **y = 1470 이하** | [확인] |
| 상단 | **y = 220 이상** | [확인] |
| 좌우 | **x 100 ~ 980** | [추정] — 19.5:9 화면에서 양쪽 약 97px이 잘린다는 계산 |

내가 쓴 자막 위치는 **y = 1290** 이었고, 2줄일 때 1250 / 1330이었다.
최대 1390까지 내려가 **하단 경계까지 80px 여유**가 남았다 [확인].

> **좌우 값은 공식 문서로 확인한 게 아니다** [추정].
> 폰에서 잘려 보인다는 관찰과 비율 계산에서 나온 값이다. 기기마다 다를 수 있다.

## 내가 당한 것 2개

### ① 확대한 줄 알고 축소했다

화면 녹화를 넣을 때, 화면 **전체**를 세로에 맞춰 넣었다.
그러면 폭이 1080에 맞춰 **줄어든다.** 나는 확대한 줄 알았다.

**결과: 글자가 29px이 됐다.** 원본에서는 42px이었다 [확인].

```
❌ 화면 전체를 넣는다           → 0.68배 축소 → 29px
⭕ 읽어야 할 부분만 잘라서 넣는다 → 1.06배 확대 → 45px
```

### ② 한 크롭으로 다 덮으려 했다

질문과 답변을 **한 번에** 보여주려 했더니 둘 다 안 읽혔다.

**크롭을 분리했다** [확인].

| 용도 | 처리 | 결과 |
| --- | --- | --- |
| 질문 컷 | 질문 영역만 잘라 1.61배 확대 | 크게 읽힘 |
| 답변 컷 | 답변 영역만 잘라 1.35배 확대 | 본문·표까지 읽힘 |

> **원칙: 한 화면에 한 가지만 읽히게 해라.** 둘 다 넣으면 둘 다 안 읽힌다.

## 검수 절차 — 이것만은 건너뛰지 마라

```
1. 완성본을 폰으로 받는다
2. 인스타 업로드 화면까지 올려본다 (게시는 하지 않는다)
3. 그 화면에서 자막 끝 글자가 보이는지 확인한다
4. 화면 녹화 구간의 글자를 실제로 읽어본다
```

**3번과 4번을 눈으로 직접 해라.** "확대했으니 보이겠지"가 내가 틀린 지점이다.

# 7장. 소스 구하기

> **이 장의 내용은 저자 개인의 경험 기록이다. 판단과 책임은 사용자 본인에게 있다.**

## 7-1. 직접 찍기 — 기본값

내 영상의 대부분은 직접 찍은 것이다 [확인].

```
□ Before / After는 반드시 같은 구도, 같은 위치에서 찍는다
□ 삼각대가 없으면 폰을 놓을 자리를 표시해둔다
□ 같은 장면을 각도만 바꿔 2~3번 찍어둔다 (편집에서 고를 수 있다)
□ 세로(9:16)로 찍는다 — 가로로 찍으면 검은 띠 처리를 해야 한다
```

내 컷 시트를 보면 **클립 11개를 찍어서 9개만 썼다** [확인]. 넉넉히 찍어두는 게 맞다.

## 7-2. 다른 데서 받은 소스 — 초기 세팅용

> **⚠️ 이 절은 계정 초기에 한정된 방법이다. 장기 운영 방법이 아니다.**

나는 초기에 해외 영상을 받아 직접 찍은 것과 섞어서 썼다 [확인].

### 반드시 알아야 할 것

**① 워터마크가 남으면 추천에서 빠진다** [확인]
인스타 공식 "추천하지 않는 릴스" 목록 1순위다. 지우는 도구는 존재한다.

**② 화질이 더 흔한 탈락 사유다** [확인]
같은 목록에 **저해상도**가 있다. 다운로드는 재인코딩이라 원본보다 떨어진다.
**워터마크만 지우고 화질을 놓치면 같은 자리에서 빠진다.**

**③ 업스케일로 없는 화질은 생기지 않는다**
키운다고 살아나지 않는다. **받을 때 최고 해상도로 받는 게 전부다.**

**④ 워터마크 제거는 저작권을 해결하지 않는다** [추정]
오히려 출처 표시를 지우는 행위다. 유리해지는 게 아니다.

### 법적 고지

```
이 책의 소스 수집 방법은 저자 개인의 경험 기록이다.
- 플랫폼 정책 위반에 따른 계정 제재는 독자 본인 책임이다.
- 저작권 관련 분쟁 역시 독자 본인 책임이다.
- 상업적 이용 전 각 플랫폼 약관과 원저작자 이용 조건을 직접 확인할 것.
- 저자는 조회수·팔로워·수익 등 어떤 결과도 보장하지 않는다.
```

## 7-3. 라이선스 소스 — 권하는 경로

**파이프라인은 100% 동일하다. 바뀌는 건 어디서 받느냐 한 줄뿐이다.**

무료 영상 소스 사이트에서 받으면 위 위험이 사라진다.

```
□ 사이트마다 라이선스 조건이 다르다 — "상업적 이용 가능" 확인
□ "출처 표기 필요" 조건이면 캡션에 넣는다
□ 받은 뒤 해상도를 확인한다 (1080×1920 이상)
```

> **계정이 자리를 잡으면 이쪽으로 옮겨라.** 초기 세팅과 장기 운영은 다른 문제다.

# 8장. 쿠팡 파트너스 연결

> **이 장은 다른 장보다 얇다. 이유를 먼저 쓴다.**

## 내가 아는 것과 모르는 것

| | |
| --- | --- |
| **[확인]** | 2개월 운영했다. **가장 잘 나온 달 100만 원**이다 |
| **[모름]** | 나머지 달 수익. 승인 조건. 평균 단가. 전환율 |

**"월 100만 원"이 아니다.** 2개월 중 한 달이 그랬다.
그 외의 숫자는 이 책에 쓰지 않는다. **내가 모르기 때문이다.**

## 구조 — 여기까지는 쓸 수 있다

```
영상 제작  →  제품 노출  →  링크 배치  →  클릭  →  구매  →  수수료
                              ↑
                    여기가 유일하게 당신이 통제하는 지점
```

### 링크를 어디 두나

| 위치 | 비고 |
| --- | --- |
| **프로필 링크** | 상시 유지 가능 |
| 캡션 | 플랫폼·상황에 따라 다름. 약관 확인 |
| 댓글 고정 | 〃 |

### 영상과 링크를 잇는 문장

프로필 링크는 **클릭할 이유가 한 줄에 있어야** 한다.

| ❌ | 왜 안 되나 |
| --- | --- |
| "프로필 링크 확인" | 클릭할 이유가 없다 |
| "많은 관심 부탁드려요" | 요청이지 제안이 아니다 |

| ⭕ | 왜 되나 |
| --- | --- |
| "영상에 나온 제품 전부 여기 ↓" | 방금 본 것의 연장이다 |
| "다이소 자취템 리스트 ↓" | 뭘 받는지 명확하다 |

**영상 안에서 링크를 언급해야 클릭이 난다.** 프로필 문구만으로는 안 난다 [추정].

## 반드시 지켜야 하는 표기

쿠팡 파트너스는 **대가성 표기 의무**가 있다.

```
이 포스팅은 쿠팡 파트너스 활동의 일환으로,
이에 따른 일정액의 수수료를 제공받습니다.
```

> **정확한 문구와 표기 위치는 반드시 공식 약관에서 직접 확인해라.**
> 약관은 바뀐다. 이 책에 적힌 문구를 그대로 믿지 마라 — 이건 진심으로 하는 말이다.

## 하지 않을 말

- "이렇게 하면 월 얼마 번다" → **모른다**
- "승인은 이렇게 하면 된다" → 내 경우만 알지 일반화할 수 없다 [모름]
- "전환율은 보통 몇 %" → 출처 없는 숫자는 쓰지 않는다

**수익 부분이 얇은 게 이 책의 정직함이다.** 두껍게 쓰려면 지어내야 한다.
